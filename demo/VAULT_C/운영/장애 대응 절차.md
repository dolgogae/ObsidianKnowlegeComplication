# 장애 대응 절차

## 분류

provider 연결 실패, schema validation 실패, source 변경, stale approval,
compile 실패, verify 실패를 구분한다. 서로 다른 오류를 재시도로만 덮지 않는다.

## 첫 행동

1. 현재 stage와 output publication 여부를 확인한다.
2. 새 provider 전송을 중단하고 journal 상태를 보존한다.
3. source나 project 파일을 임의로 수정하지 않는다.
4. [[운영/provider 장애 runbook]] 또는 [[운영/백업 검증]]의 해당 절차를 따른다.
5. 복구 후 같은 artifact를 독립 verify한다.

사용자 안내는 [[고객/지원 문의 패턴]]의 표현을 사용한다.
