# 장애 대응

## provider timeout

작업을 failed로 기록하고 partial response를 proposal로 저장하지 않는다. 연결을
확인한 뒤 같은 task key로 다시 실행한다.

## 검증 실패

output을 배포하지 않는다. source snapshot, integration plan, checksum 차이를
확인하고 임의로 manifest를 수정하지 않는다.

## publication 이후 durability 경고

완전한 directory가 이미 보일 수 있으므로 삭제를 rollback으로 간주하지 않는다.
별도 verify와 filesystem 상태 확인 후 운영 판단을 기록한다.
