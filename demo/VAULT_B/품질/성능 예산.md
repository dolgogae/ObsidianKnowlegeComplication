# 성능 예산

파일럿은 문서 수백 개 규모에서 terminal이 계속 반응하고 작업별 진행 상황이
보이는 것을 목표로 한다. provider latency와 local parsing 시간을 분리해서
측정한다.

embedding은 stable document 순서로 요청하고, response vector 수와 dimension을
검증한다. candidate 수에는 명시적 상한을 두되 taxonomy coverage를 줄이는
fallback으로 사용하지 않는다.

장기 목표인 대규모 Vault 처리 시간과 memory 한도는 benchmark를 실제로 실행한
뒤 통과 여부를 기록한다. 작은 demo 결과를 대규모 성능 증거로 일반화하지 않는다.
