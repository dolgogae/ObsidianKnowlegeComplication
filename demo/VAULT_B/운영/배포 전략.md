# 배포 전략

개발 파일럿은 저장소에서 pinned dependency로 release binary를 빌드해 사용한다.
공식 installer가 배포되기 전에는 자동 update를 운영 절차에 포함하지 않는다.

새 build는 doctor, integration smoke, compile, independent verify를 통과한 뒤
제한된 파일럿 사용자에게 전달한다. application binary 배포의 서명과 사용자가
만든 지식 산출물의 검증을 같은 것으로 설명하지 않는다.

rollback은 이전 binary와 이전에 검증된 output directory를 유지하는 방식이다.
새 output으로 기존 directory를 덮어써서 되돌리지 않는다.
