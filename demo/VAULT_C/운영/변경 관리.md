# 변경 관리

source set, provider route, taxonomy, proposal, critic, approval 중 하나가 바뀌면
영향받는 downstream state를 새 revision으로 만든다. 이전 상태를 덮어쓰거나
새 입력에 과거 승인을 붙이지 않는다.

변경 전에는 [[거버넌스/승인 역할]]에서 owner를 확인한다. 데이터 등급이 바뀌면
[[거버넌스/데이터 분류]]에 따라 disclosure를 다시 판단한다. 결과 publish 전에는
[[운영/백업 검증]]과 independent verify를 수행한다.

긴급 변경도 provenance와 rationale을 생략하는 예외가 아니다.
